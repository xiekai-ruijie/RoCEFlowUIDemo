集合通信反演算法

01 为什么需要反演

在没有服务器访问权限的条件下，仅通过网络流量分析，逆向推导 GPU 间的通信关系、并行策略和任务归属——相当于"只听电话铃声，就能推断谁在和谁开会"。

RDMA / RoCEv2 GPU 集合通信 大模型训练
核心矛盾：运维需要精准定位训练任务的性能瓶颈，但通常没有 GPU 节点的登录权限。通信反演在"黑盒"条件下，从网络层流量反推应用层行为。

02 AI 分布式训练并行策略

大模型训练将 GPU 分布在多台服务器上协同工作。不同的并行策略决定了 GPU 间如何交换数据，也决定了网络流量的模式。

原理：每张 GPU 持有完整模型副本，处理不同数据批次。前向/反向各自独立完成，通过 AllReduce 汇总梯度。

流量特征：AllReduce 通信，周期性同步，流量大。

原理：将一层模型参数水平切分到多张 GPU。计算后通过 AllReduce 同步中间激活值。通常限制在同一节点内（NVLink 高带宽）。

原理：模型按层切分为多个 Stage。数据像流水线一样流过各 Stage，Stage 之间通过 Send/Recv（P2P） 同步激活和梯度。

原理：MoE 模型中不同 token 需要路由到不同专家子网络。通过 All-to-All 通信做 token 的跨 GPU 分发和收集。

典型组合：节点内 TP（NVLink），节点间 DP（RoCEv2 AllReduce），跨 Pod PP（P2P 通信量小）。反演算法需识别这些混合模式。

03 集合通信原语

并行策略决定了"怎么分工"，集合通信原语则定义了 GPU 之间"怎么交换数据"。点击卡片查看动画演示。

点对点

Send / Recv

两个 GPU 之间的直接数据传输。最基础的通信原语。

用途：流水线并行相邻 Stage 间传递

1 对多

Broadcast

一个 GPU 将数据完整复制到所有其他 GPU。操作后所有 GPU 数据相同。

用途：模型参数初始化同步

1 对多

Scatter

一个 GPU 将数据分成 N 份，每份发给一个 GPU。各 GPU 持有不同数据。

用途：张量并行初始化参数分发

多对 1

Gather

所有 GPU 将各自数据发送到一个目标 GPU。与 Scatter 相反。

用途：张量并行结果汇总

多对 1

Reduce

所有 GPU 数据经 SUM/MAX 等运算，结果只留在一个 GPU 上。

用途：AllReduce 内部的 reduce 步骤

多对多

ReduceScatter

先按维度做 Reduce，再将结果 Scatter 到各 GPU。每个 GPU 获得一部分归约结果。

用途：AllReduce 第一阶段

多对多

AllGather

先 Gather 再 Broadcast——所有 GPU 都获得所有 GPU 的数据。

用途：AllReduce 第二阶段；TP 前向输出

多对多

AllReduce ★

所有 GPU 数据做 Reduce 后，结果分发到所有 GPU。训练中最核心的原语。

用途：DP 梯度同步；TP 激活同步

多对多

All-to-All

每个 GPU 向其他所有 GPU 发送不同的数据片段。AllGather 的扩展（各 GPU 收到不同数据）。

用途：MoE 专家并行 token 路由

AllReduce 两种实现：方式一（Reduce + Broadcast）存在 GPU0 瓶颈；方式二（ReduceScatter + AllGather）带宽均匀分散，是主流实现。下面详细演示 Ring AllReduce。

05 RoCEv2 与报文采样

智算网络使用 RoCEv2 协议传输，基于 RC 可靠连接，接收方返回 ACK 确认报文。ACK 报文携带的五元组和 PSN 是通信反演的关键数据来源。

采样方案对比

方案方式优点缺点
方案一全量采样 RoCEv2 流量信息完整设备性能压力大
方案二（推荐）周期性随机采样（1~10ms）低负载，利用训练周期性需合理配置采样频率
流表机制：CPU 维护流表，记录"谁在和谁通信"。每 10 秒定期上报控制器，60 秒无更新则自动老化删除。

08 AI Job 检测应用

同一训练任务的所有 GPU 构成一个"通信域"。通过检测通信域的变化，可以判断任务的启动、结束或故障迁移。

通信域变化时间线

10:00:00
Job-1 启动 — 通信域 [GPU_1..GPU_8] 出现，TP8 模式
10:05:00
Job-2 启动 — 通信域 [GPU_9..GPU_16] 出现，TP4DP2 模式
11:45:00
Job-2 结束 — 通信域 [GPU_9..GPU_16] 消失
11:50:00
Job-3 启动 — 通信域 [GPU_9..GPU_16] 重新出现（碎片化调度）
12:30:00
Job-1 结束 — 通信域 [GPU_1..GPU_8] 消失
实际价值：集群资源管理、任务调度优化、故障快速定位——无需登录服务器即可掌握全集群训练状态。
